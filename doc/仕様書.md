## 1. プロジェクト概要

### 1.1 サービス目的

**広島県の社会人テニス大会を、誰でも簡単に探せるデータベース。**

### 1.2 解決する課題

広島県内の一般・社会人向け大会情報は、テニス協会、スクール、クラブ、各種団体など複数の情報源に分散している。

各情報を横断して検索できる形に整理する。

### 1.3 想定ユーザー

- 広島県の社会人テニスプレイヤー
- 一般大会に出場したい人
- 自分のレベルに合う大会を探す人
- 地域・種目・性別等で大会を横断検索したい人

## 4. 検索仕様

### 4.1 検索条件

| 条件 | 内容 | DB項目 |
|---|---|---|
| 開催時期 | 月・期間等 | `start_date` / `end_date` |
| 市町村 | 広島市、呉市、東広島市、福山市、尾道市、三原市等 | `city` |
| 種目 | シングルス、ダブルス、MIX、団体戦等 | `event_type` |
| 性別 | 男子、女子、MIX、男女共通等 | `gender` |
| レベル | A/B/C/D/AB/CD/Open/初心者等 | `level` |
| 参加資格 | 非会員、他市協会員、ビジター、年齢条件等 | `external_allowed` / `other_city_allowed` / `eligibility_category` / `age_condition` |

### 4.2 URLパラメータ

検索フォームは条件をURLクエリパラメータとして `/tournaments` に渡す設計。

例：

```text
/tournaments?city=広島市&eventType=ダブルス&level=B
```

現在は一覧取得までがSupabase化済みで、URL条件をSupabase検索へ反映することが次工程。

## 6. DB設計

### 6.1 tournaments

| カラム | 内容 |
|---|---|
| `id` | 大会ID（主キー） |
| `name` | 大会名 |
| `organizer_id` / `organizer_name_raw` | 主催者 |
| `venue_id` / `venue_name_raw` | 会場 |
| `city` | 市町村 |
| `date_text` | 表示用開催日 |
| `start_date` / `end_date` | 検索用開催日 |
| `event_type` | 種目 |
| `gender` | 性別 |
| `level` | レベル |
| `eligibility` | 参加資格 |
| `eligibility_category` | 参加資格カテゴリ |
| `membership_required` | 会員条件 |
| `external_allowed` | 外部参加可否 |
| `other_city_allowed` | 他市協会員可否 |
| `age_condition` | 年齢条件 |
| `fee_text` | 参加費 |
| `deadline_text` / `deadline_date` | 申込期限 |
| `application_method` | 申込方法 |
| `official_url` | 公式URL |
| `status` | 募集状況 |
| `notes` | 備考 |
| `search_tokens` | 検索用文字列 |
| `data_quality_note` | データ品質メモ |
| `last_checked_at` | 最終確認日時 |
| `created_at` / `updated_at` | 作成・更新日時 |

### 6.2 関連テーブル

- `organizers`：主催者マスタ
- `venues`：会場マスタ
- `event_sources`：大会情報の出典URL・確認日時等

### 6.3 DB制御

主要検索項目等にインデックスを設定済み。

主要4テーブルはRLSを有効化し、現状は `anon` / `authenticated` によるSELECTを許可。

書き込み権限は認証・管理者権限設計と合わせて追加予定。

## 7. データ品質

主催者公式サイト、テニス協会、スクール、クラブ等の一次情報を中心に収集する方針。

`event_sources` で出典を追跡し、`last_checked_at` 等で確認状況を管理する。

AIやユーザー入力を無条件で公開せず、最終的な更新判断は管理者が行う。

現在31大会をSupabaseに登録済み。

---

## 8. 情報修正提案

### 8.1 基本フロー

```text
大会詳細
  ↓
「この情報を修正する」
  ↓
現在値・修正値・理由・根拠URL等を入力
  ↓
修正提案保存
  ↓
AIチェック
  ↓
管理者確認
  ↓
承認 / 差し戻し / 却下
  ↓
承認時に大会DB更新
  ↓
変更履歴保存
```

### 8.2 AIチェック

- 根拠URL確認
- 日付・参加費等の一致確認
- 既存情報との矛盾検出
- 重複・同一大会候補検出
- 管理者確認用チェック結果作成

AIは公開判断を行わず、最終的な公開・DB更新は管理者承認とする。
