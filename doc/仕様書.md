# 1. サービス概要

## 1.1 サービス名

広島テニスポータル

旧称：広島テニスDB / 広島テニスDBサイト

## 1.2 サービスの目的

広島県の一般・社会人テニス大会を、日程・エリア・種目・レベル・性別・参加資格・申込状況などの条件から探せるようにする。

利用者にとっての最終的な目的は、

> 広島で、自分が参加できるテニス大会をすぐに見つけること

とする。

## 1.3 想定ユーザー

- 広島県内で一般・社会人テニス大会を探している人
- 自分のレベルに合う大会を探したい人
- 男子・女子・男女共通などの条件から大会を探したい人
- 市町村・会場から大会を探したい人
- 申込期限が近い大会を探したい人

## 1.4 対象情報

現時点では広島県内の一般・社会人向けテニス大会が中心。

将来的にテニスコート、スクール、ガット張り等の関連情報へ拡張する。

## 5.2 大会検索・一覧

URL：/tournaments

### 基本条件

| 条件 | 選択肢 / 内容 |
|---|---|
| キーワード | 大会名・会場・主催者等 |
| 日程 | すべて / 今月 / 3か月以内 / 6か月以内 |
| エリア | 登録大会に存在する市町村 |
| 種目 | シングルス / ダブルス / MIXダブルス / 団体戦 / 交流大会 / ベテラン |
| レベル | A / B / C / D / AB / CD / オープン |
| 申込 | まだ申込可能 / 7日以内に締切 / 30日以内に締切 / 指定なし / 締切情報なし |

### 詳細条件

- 性別：男子 / 女子 / 男女
- 参加資格：非会員でも参加OK / 他市協会員OK / ビジターOK
- ステータス：募集中 / 開催予定 / 終了

### 初期状態

標準では「まだ申込可能」を選択した状態。

deadline=open の場合、deadline_date が今日以降の大会を表示する。

「指定なし」にした場合も、開催日が今日以降の大会を表示する。

### キーワード検索対象

- name
- organizer_name_raw
- venue_name_raw
- city
- search_tokens
- notes

### レベル検索

CDを指定した場合、CDとC/Dの両方を検索対象とする。

ABを指定した場合、ABとA/Bの両方を検索対象とする。

### 申込条件

7日以内に締切：
今日から7日以内のdeadline_date。

30日以内に締切：
今日から30日以内のdeadline_date。

締切情報なし：
deadline_dateがNULL。

### ページング

- 1ページ20件
- pageをURLで保持
- ページ移動後も検索条件を保持

### 0件時

検索結果が0件の場合、

- 申込条件を外す
- 全条件をクリア

の導線を表示する。

### 絞り込み条件表示

検索結果上部に現在の条件を表示する。

# 7. 大会詳細

URL：/tournaments/[id]

表示内容：

- ステータス
- レベル
- 確認日
- 大会名
- お気に入り状態
- 開催日
- 会場
- 種目
- 参加費
- 申込締切
- 参加資格
- 主催者
- 性別
- クラス
- 申込方法
- 備考
- データ品質メモ
- 同じ主催者の今後の大会
- 情報源

### 主なアクション

- 申込ページを開く
- 公式情報を見る
- 情報を修正する
- お気に入り登録

### URLの扱い

application_method がURLなら申込ページを優先して表示する。

application_method がURLでなく、official_urlがURLなら公式情報を表示する。

申込URLと公式URLが異なる場合は、それぞれを別アクションとして表示する。

### スマートフォン

- 大会詳細の主要アクションを画面下部に固定
- 固定アクションを使用するため、本文内の通常アクションボタンは非表示
- 詳細ページでは通常のスマホ下部ナビを非表示
- アクション数に応じて1列 / 2列で配置
- 大会情報テーブルは各項目の区切りが分かる枠線を表示

# 12. 情報修正提案

URL：/tournaments/[id]/suggest

## 目的

大会情報に誤りや古い情報がある場合に、利用者から修正案を受け付ける。

## 主な入力項目

- 修正対象項目
- 現在の値
- 修正後の値
- 修正理由
- 根拠URL

## 処理フロー

大会詳細
→ 情報を修正する
→ 修正内容入力
→ POST /api/correction-proposals
→ correction_proposals保存
→ 管理者確認
→ 承認 / 却下
→ 承認時に大会DB更新
→ correction_proposal_histories保存

現在はAIチェックを挟んでいない。

- 公式URL未設定

- 最終確認が30日以上前
- 申込締切経過
- 締切日を要確認
- 品質メモあり

## 優先確認

次のような問題を優先確認対象とする。

- 申込締切経過
- 開催日未設定
- 公式URL未設定
- 公式URL形式要確認

匿名ユーザー・認証済みユーザーが送信できる：

admin_usersに登録された認証ユーザーのみ：

- correction_proposals閲覧
- correction_proposal_histories閲覧
- contact_messages閲覧
- ingestion_jobs参照 / 登録 / 更新

承認・却下や大会直接更新は管理者確認を行うRPCを使用する。

- 修正提案フロー

- PDFからの情報抽出

- DBとの差分検出
- 重複大会検出

- 定期的な更新候補作成

AIだけで公開情報を確定しない。

AIは候補作成・チェック補助までとし、

AI
→ 候補 / チェック結果
→ 管理者確認
→ 公開DB更新

の順で運用する。

# 37. 最終的なサービス像

広島のテニスプレイヤー
→ 自分に出られる大会を検索
→ 大会詳細を確認
→ 開催日・参加費・参加資格・締切を確認
→ 公式情報・申込ページへ移動
→ お気に入り保存
→ 将来的に通知

この一連の流れを少ない操作で完結できることを目指す。

現在は、そのための大会データベースと管理基盤を構築している段階。
